# 웹앱 디자인 시스템 & UI 재구축 — 설계 문서

- 작성일: 2026-09-06
- 상태: 설계 확정, 구현 계획 대기
- 선행 문서: [스팀 저평가 게임 발굴 웹앱 설계](2026-09-05-steam-hidden-gems-design.md) — 이 문서는 그 스펙의 "웹앱" 절을 대체·구체화한다.

## 배경

Phase B(collector) 구현이 끝나 실데이터 수집이 가능해졌다. `web/`에는 최소
뼈대(필터 폼 + 스타일 없는 `GameCard`)만 있고, 포트폴리오 심사관이 30초~1분
안에 "뭘 보여주는 프로젝트인지" 파악할 수 있는 수준의 완성도가 아니다. 이
문서는 그 웹앱을 디자인 시스템 기반으로 재구축하는 범위를 정의한다.

**백엔드는 변경하지 않는다.** 기존 `GET /games/gems`가 카드·차트·상세 모달에
필요한 필드를 모두 반환하므로 이번 작업은 `web/` 디렉토리에 한정된 프런트엔드
작업이다.

## 목적과 범위

- **1차 목적**: 포트폴리오 데모. 채용담당자가 짧은 시간 안에 "품질 대비
  저평가된 게임을 찾는 도구"라는 가치 제안과 판정 근거를 이해하게 만든다.
- **페이지 구성**:
  1. 메인 페이지 (`/`) — 필터, 사분면 산점도, 랭킹 카드 그리드, 상세 모달.
  2. 방법론 페이지 (`/about`) — 스코어링 로직·데이터 소스·한계를 두괄식으로
     설명 (결론 → 방법 → 한계). `docs/superpowers/specs/2026-09-05-*` 내용을
     사용자용 문장으로 재작성.
- **스코프 아웃**: 로그인/개인화/찜하기, 실시간 갱신, 게임 상세 전용 라우트
  (모달로 대체), 다국어(한국어만).

## 디자인 토큰

### 컬러 (다크 전용, 라이트 모드 없음 — 포트폴리오 데모 스코프이므로 단일 테마로 절제)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg-void` | `#12141A` | 페이지 배경 |
| `--surface` | `#1B1E27` | 카드/패널/필터 바 |
| `--surface-raised` | `#242835` | 모달, 호버 상태 |
| `--border` | `#2E3340` | 헤어라인 구분선 |
| `--ink-primary` | `#EDEEF2` | 본문/제목 |
| `--ink-secondary` | `#9BA0AF` | 보조 텍스트, 라벨 |
| `--ink-muted` | `#6A6F7E` | 3차 텍스트, 비강조 산점도 점 |
| `--accent-gem` | `#7C6AF0` | "숨은 명작" 강조 전용 (배지, gem 영역, 주요 CTA) — 이 색은 다른 용도로 쓰지 않는다 |
| `--accent-gem-wash` | `#7C6AF0` @ 12% alpha | 사분면 차트의 gem 영역 배경 음영 |

컬러는 accent-gem 한 곳에만 과감하게 쓰고 나머지는 그레이스케일로 절제한다.
"거의 검정 배경 + 형광 그린/버밀리언 단일 액센트"라는 흔한 AI 생성 다크 테마
기본값을 피하기 위해, 배경은 차가운 그래파이트(순수 블랙 아님)로, 액센트는
"보석(gem)" 컨셉에서 자수정/보라 계열로 잡는다.

### 타이포그래피

- 폰트: **Pretendard** (Variable) 단일 패밀리. 한글·라틴 모두 지원하고
  weight 범위가 넓어 두 번째 서체 없이 위계를 만들 수 있다. `next/font/local`로
  자체 호스팅.
- 스케일:
  | 역할 | 크기/행간 | weight |
  |---|---|---|
  | Display (헤드라인) | 40/48px (모바일 28/36) | 700 |
  | H2 (섹션 제목) | 22/28px | 600 |
  | Body | 15/24px | 400 |
  | Data label (백분위·가격·배지) | 13/18px, `font-variant-numeric: tabular-nums` | 500 |
  | Caption | 12/16px | 400, `--ink-secondary` |
- ALL-CAPS 라벨, 넓은 트래킹의 eyebrow, 중간점(·)으로 이은 메타 문자열은
  쓰지 않는다.

### 레이아웃

- 컨테이너 최대 너비 1120px, **좌측 정렬** (마케팅 페이지의 중앙정렬 히어로
  지양 — 첫 픽셀부터 "동작하는 툴"처럼 보이게 한다).
- 브레이크포인트: 모바일(<640px) 1열, 태블릿(640–1024px) 필터/차트 세로 스택,
  데스크톱(≥1024px) 필터/차트 2열 + 카드 그리드 3열.
- 간격 스케일: 4px 배수 (4/8/12/16/24/32/48).

```
헤더: 로고/타이틀 ······················ 방법론 링크
헤드라인 (두괄식 한 줄) + 서브카피 한 줄

┌ 필터 패널 ─────────────┐  ┌ 사분면 산점도 ─────────┐
│ 장르 (select)          │  │ y=품질 백분위          │
│ 태그 (text input)      │  │ x=노출 백분위          │
│ 최대 예산 (number)     │  │ 좌상단 = gem 영역 강조 │
│ [검색]                 │  │ (배경 음영 + 라벨)     │
└────────────────────────┘  └────────────────────────┘

랭킹 카드 그리드 (3열 데스크톱, 헤어라인 구분 — 균일 shadow 카드 kit 지양)
[카드] [카드] [카드]
카드 클릭 → 모달(점수 breakdown, 태그, 판정 근거 문구)
```

## 컴포넌트 인벤토리

`web/components/`에 다음을 추가/재작성한다 (각각 독립적으로 이해·테스트
가능해야 함):

| 컴포넌트 | 책임 |
|---|---|
| `FilterPanel` | 장르/태그/예산 입력, 상태는 URL 쿼리스트링과 동기화 |
| `GemScatterChart` | quality_pctile(y) vs exposure_pctile(x) 산점도, gem 영역(좌상단) 강조, hover 툴팁, 접근성 테이블 뷰 대체 |
| `GameCard` | 기존 컴포넌트 재작성 — 헤어라인 구분, hover 시 강조, 클릭 시 모달 오픈 |
| `GameDetailModal` | 점수 breakdown(백분위 두 값 + 산식 설명), 태그 전체, 근거 문구 |
| `ScoreBadge` | "상위 N%" / "하위 N%" 배지 — 카드와 모달에서 재사용 |
| `EmptyState` | 필터 결과 0건일 때: 필터를 넓히라는 안내 (사과하지 않는 톤) |

## 사분면 산점도 (dataviz 스킬 적용)

- **폼**: 산점도. 두 백분위 지표의 관계 + 이상치(=저평가 게임) 식별이 목적이므로
  막대/라인이 아닌 산점도가 정답.
- **축**: x = exposure_pctile (노출 백분위, 낮을수록 왼쪽), y = quality_pctile
  (품질 백분위, 높을수록 위). 둘 다 0~1 → 0~100%로 표시.
- **강조 방식**: 색을 카테고리 구분에 쓰지 않는다. 좌상단(고품질·저노출) 영역에
  `--accent-gem-wash` 배경 음영 + "숨은 명작 구간" 텍스트 라벨을 깔고, 그 영역
  안에 들어오는 점만 `--accent-gem`으로 채운다. 나머지 점은 `--ink-muted`.
  → 색 하나에만 의존하지 않도록 배경 음영 + 라벨을 함께 쓰는 이중 인코딩.
- **인터랙션**: 점 hover 시 게임명 + 두 백분위 값 툴팁. 점 클릭 시 해당 게임의
  `GameDetailModal` 오픈 (카드 클릭과 동일한 진입점).
- **접근성**: 차트 아래 "표로 보기" 토글로 동일 데이터를 테이블로 제공.
- **데이터 소스**: 카드 그리드와 동일한 `/games/gems` 응답을 재사용한다(차트용
  별도 API 호출 없음). 필터가 없을 때는 `limit`을 늘려(예: 200) 산점도가
  충분한 밀도를 갖게 하고, 카드 그리드는 그중 상위 N개(예: 30개)만 렌더링한다.

## 데이터 흐름

- 상태는 기존 설계(`web/app/page.tsx`)와 동일하게 **URL 쿼리스트링에 필터
  상태를 유지**하는 방식을 그대로 쓴다 (뒤로가기/공유 가능).
- 한 번의 fetch 결과를 `FilterPanel` 하위의 차트와 카드 그리드가 함께
  소비한다 (단일 소스, prop drilling 또는 최소한의 context로 충분 — 별도
  상태관리 라이브러리 불필요).
- 상세 모달은 이미 메모리에 있는 게임 객체를 그대로 쓴다 (별도 API 호출 없음).

## 기술 스택

- Tailwind CSS 도입 (`web/`에 신규 설치). 디자인 토큰은 `tailwind.config.ts`의
  `theme.extend.colors`/`fontFamily`에 등록해 컴포넌트 전역에서 재사용.
- 차트는 별도 차트 라이브러리 없이 SVG로 직접 구현한다 (데이터 포인트 수가
  수백 개 수준이라 라이브러리 없이도 충분하고, dataviz 스킬의 mark spec을
  그대로 지킬 수 있다 — 2px 라인, 4px 라운드, 8px 이상 마커, hover 레이어).
- Pretendard는 `next/font/local`로 자체 호스팅 (외부 CDN 의존 없음, Vercel
  배포에 유리).

## 테스트

- 기존 `web/components/GameCard.test.tsx` 패턴을 유지 (Vitest + Testing
  Library).
- `GemScatterChart`: gem 영역 판정 로직(좌상단 강조 여부)에 대한 단위 테스트.
- `FilterPanel`: URL 쿼리스트링 동기화 테스트.
- 시각 회귀 테스트는 스코프 아웃 (포트폴리오 데모 규모에 과함).

|---|---|
